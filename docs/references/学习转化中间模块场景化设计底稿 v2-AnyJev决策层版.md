# 学习转化中间模块场景化设计底稿 v2-AnyJev决策层版

> **版本说明**：v2 新增 "AnyJev 决策层设计" 章节，将 AnyJev 决策框架与学习中间模块设计合并，日期 2026-09-30。v1 全部内容保留。

---

## 〇、总览：输入 → 转化 → 输出

| 段 | 用户实际体验 | 失败表现 |
|---|---|---|
| 输入 | 看课、看书、刷题、听讲、查资料 | 输入很多但"懂了不会用"；输入少却"感觉懂了" |
| **转化（核心）** | 从例子提炼规律、建判别/联结模型、拆解大问题、练出肌肉记忆 | **卡点几乎都在这里**：特征抓错、边界不清、只记答案、无反馈、无变式 |
| 输出 | 解题、表达、交付、实战 | 未见情况验证失败、离开 AI 不会做、考场/实战掉链子 |

**设计原则**：中间模块不做"更多输入"，做"转化动作"——即把输入材料转成学习动作（分型、配料、拆解、出变式、建反馈、验收）。

## 一、按学习对象类型：场景 / 卡点 / 中间模块动作 / AI 介入

### 1. 判别模型类（学"是什么/是不是"）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 概念辨析（如"相关 vs 因果"、合同法术语、诊断标准、产品分类） |
| 用户典型卡点 | ① 只记定义不会判别实例；② 相似概念分不清（把 A 当 B）；③ 只见过正例、没见过反例/边界例，一到边缘情况就错；④ 凭"感觉像"判断而非按特征逐条比对 |
| 中间模块应做的转化动作 | 特征拆分（把内涵拆成"某某性"逐条比对）→ 正例/反例/边界例三件套齐备 → 对比例组（A正例&B负例 + 反之）→ 互斥 vs 多重判别判断 → 四类归因（定义不清/边界不清/特征抓错/过度概括）→ 未见情况验收 |
| AI 介入环节 | 出正反例与边界例（要题不要答案）、随机抽题考核、按四类归因定位卡点后自动补对应材料 |

### 2. 思考型技能类（解题 / 推理）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 数学题、编程算法、逻辑推理、案例分析 |
| 用户典型卡点 | ① 捷径记忆：背套路答对但不会推理（换数字/换包装就懵）；② 推理链在某节点断掉不自知；③ 只做例题不做变式；④ 看不懂题意（输入输出未明确） |
| 中间模块应做的转化动作 | 变式五维度出题（换数字/包装/问法/干扰/条件）→ 口述推理链暴露断点 → 节点图诊断 → 拆条件逐节点补漏 → 未见情况重测 |
| AI 介入环节 | 生成变式题与干扰项、听用户口述推理链后标出断点位置、按节点图推送针对性练习 |

### 3. 运动型技能类（操作 / 身体 / 手熟）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 健身动作、乐器、打字、手术操作、驾驶、软件操作流畅度 |
| 用户典型卡点 | ① 看会了但手跟不上（执行层缺）；② 不知道对错（感知层缺，无人反馈）；③ 一紧张/一换环境就变形（稳定层缺）；④ 练得多但没改（练≠改） |
| 中间模块应做的转化动作 | 定档（A 自带反馈 / B 需外挂 / C 延迟反馈）→ 分层定位（感知/执行/稳定）→ 建最短延迟反馈环（谁/何时/怎么判对错）→ 慢练原则（慢练才能学、快只能验）→ 一次只改一个变量 → 录像回看 |
| AI 介入环节 | 录像逐帧标错、设计反馈提示时机、生成"拆小练习"清单、记录改进变量清单 |

### 4. 语言型技能类（外语 / 表达）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 学外语、演讲、写作、口语表达 |
| 用户典型卡点 | ① 被动词汇错觉：能读懂/听懂但说不出来；② 听说读写混在一起练，哪个都没练透；③ 输出没有台阶，直接硬上即兴就卡死；④ 输入太难（听不懂）或太简单（无质变） |
| 中间模块应做的转化动作 | 四维分离（听说读写分别练）→ 攻主动词汇（能自己用出来）→ 输出三台阶（跟读→复述→即兴）→ 逐级撤辅助 L1-L4 → 输入压到"能懂七成"＋保证主动产出量触发质变点 |
| AI 介入环节 | 扮演陪练（跟读打分、复述纠错、即兴接话）、按能懂七成原则调节输入难度、撤辅助阶梯进度管理 |

### 5. 决策类（隐性经验）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 管理、投资、销售判断、职业选择、带团队 |
| 用户典型卡点 | ① 看书/上课无效（隐性经验 0:10，无场景就无法学）；② 低频决策没机会积累经验；③ 好决策坏结果后自我怀疑（把运气当能力/把结果当判据）；④ 决策时凭感觉说不清权衡逻辑 |
| 中间模块应做的转化动作 | 定档（高频/低频/专业判断）→ 分层查缺（模式识别/权衡规则/行动惯例）→ 六行决策日志 → 坏决策 vs 坏结果四象限复盘 → 反馈加速器（拆小/借例/预写）→ 概率化表达 |
| AI 介入环节 | 提供决策日志模板与复盘提问、用真实案例做"借例推演"、当"预写预测"的对照端、帮助把判断写成概率化表述 |

### 6. 信息型类（资料 / 知识管理）

| 维度 | 内容 |
|---|---|
| 典型学习场景 | 查资料、读文档、软件操作、行业动态、"想学点 X"的泛需求 |
| 用户典型卡点 | ① 把"查得到的信息"当知识死记（时间浪费）；② 收藏即学会（堆信息无索引）；③ 想学时找不到入口、找到了过时；④ 分不清该学还是该查 |
| 中间模块应做的转化动作 | 三问判据（能不能查/会不会变/使用频率）→ 判定为信息型则只建索引不存储 → 索引三要素（名称/入口/有效期）→ 目标 30 秒可查 → 双向升级规则（用三次以上升级记忆型，查五次记不住降级信息型） |
| AI 介入环节 | 生成索引条目（名称/入口/有效期）、回答"该学还是该查"的分型咨询、按升级规则提醒转为记忆型/降级 |

## 二、学习卡点高频场景清单

| 场景 | 卡点根因 | 解法入口（对应中间模块） |
|---|---|---|
| 备考 / 考证 | 把"考过"当靶导致背鉴定点冒充能力；考点未分优先级，80% 无效劳动；按章节顺序练而非按能力环节练 | 靶改写（考过→能做出 Y）→ 考点三区分类（必须练/只需认/可不管，如 252→55）→ 按环节聚类练 → 三档验收题 |
| 学外语 | 被动词汇错觉、听说读写混练、输出无台阶、输入难度不当 | 四维分离 → 攻主动词汇 → 输出三台阶撤辅助 → 能懂七成质变点 |
| 编程入门 | 看教程/抄代码冒充会写；语法当信息背；调试只记见过的报错 | 八类型分型（联结为主）→ 明确输入输出 → 变式五维（换需求/包装/干扰）→ Debug 用负例缩小候选 → 撤 AI 验收（独立写一次） |
| 投资研究 | 个案当规律（以偏概全）；分不清信息与知识；只背结论不会验证 | 信息 vs 知识区分 → 因素材料列变量/关系材料定方向 → 样本外未见情况验证 → 决策日志 + 坏决策≠坏结果复盘 |
| 练技能（健身/乐器/操作） | 无反馈、练≠改、看会了手不会、换环境就变形 | 定档分层 → 建最短延迟反馈环 → 慢练 + 一次只改一个变量 → 录像回看 |
| 概念学习（考试/法务/医学术语等） | 只记定义、相似概念分不清、没见反例 | 特征拆分 → 正反例+边界例 → 对比例组 → 四类归因补料 |
| 管理 / 领导力等软技能 | 当知识学但本质是隐性经验；无场景看书无效；低频决策无反馈 | 隐性经验判定（0:10 配比）→ 决策三档 → 六行日志 + 借例推演 + 预写预测 |
| "收藏即学会"型学习 | 信息型当记忆型学；堆收藏无索引；入口过期 | 三问判据分型 → 只建索引（名称/入口/有效期）→ 30 秒可查 → 双向升级规则 |
| 读论文 / 教材 | 顺序阅读通篇记；例题当例子看而非当习题做；看懂=学会 | 例习循环（例题变习题）→ 遗例转习 → 判别/联结目标先行 → 未见情况验证 |
| AI 辅助学习失控 | 让 AI 给答案、离开 AI 不会做、被 AI 代做产生"会了"错觉 | AI 分工三层（替记替查/出题出料/陪练镜子）→ 要题不要答案 → 撤 AI 验收 |

## 三、现有资料中的 AI 协作方法（AI 角色介入方式）

### 1. AI 分工三层（按学习类型定角色）

| 层 | AI 角色 | 适用类型 | 示例 |
|---|---|---|---|
| 替记 / 替查 | 记忆外挂、检索入口 | 记忆信息、信息型 | 帮记鉴定点、建索引、回答"该学还是该查" |
| 出料 / 出题 | 材料生产器、判官 | 判别型、联结型 | 生成正反例/边界例/变式题/材料配方、随机抽题考核 |
| 陪练 / 镜子 | 练习对手、反馈镜 | 思考型、运动型、语言型、决策型 | 当口语陪练、听口述推理链标断点、录像标错、决策日志复盘提问 |

**红线**：第三层 AI 绝不替做——思考、运动、语言、决策的"做"必须用户自己完成，AI 只提供反馈与陪练。

### 2. AI 要题不要答案

- 正确姿势：让 AI 生成变式题、反例、边界例、陪练脚本、随机抽题，而不是直接给答案。
- 原因：给答案会绕过学习本身（转化段缺位），用户得到的是"信息"而非"模型"。

### 3. 撤 AI 验收法

- 判据：学完后把 AI 拿走，独立完成一次任务；做不出来＝只会操作 AI，不是会该技能。
- 用法：作为所有 AI 辅助学习路径的最终验收环节（对应"未见情况验收"）。

### 4. 学习任务卡（AI 的标准输入格式）

- 把学习目标写成任务卡：靶（要能做出什么）→ 分型 → 材料配方（上料:下料）→ 验收题（三档）→ 不学清单。
- 作用：让 AI 按统一格式产出学习材料，也是"一键生成器"的接口设计基础。

### 5. AI 辅助材料生产（对应《学习观》原文方法）

- 把学习观理论框架输入大模型，请其按判别/联结模型生成例子、习题、特征对比、类比，并鉴别其正确性。
- 适用：缺例子/习题/讲解时，AI 负责"出料"，用户负责"转化"。

### 6. AI 介入的通用原则

| 原则 | 说明 |
|---|---|
| 分型先行 | 先判学习类型再决定 AI 介入方式，避免"万能陪练"错配 |
| 转化不外包 | AI 只做输入侧（出料）与输出侧（验收/反馈），中间的模型建构必须用户完成 |
| 反馈闭环 | AI 的每次输出都要指向下一步动作（补料/重练/撤辅助），而不是"答案终结" |
| 验收可撤 | 所有 AI 协作路径都以"撤 AI 独立完成"为终点 |

## 四、设计落地要点（组件化）

1. **组件入口**：一句话描述学习目标 → 自动分型 → 输出类型卡片（配比/验收/AI角色）。
2. **转化动作包**：每种类型内置一组"转化动作"（见第一节中间模块列），组件按卡点触发对应动作。
3. **卡点诊断器**：用户描述"不会"的具体表现 → 四类归因/分层定位 → 推荐补料或重练路径。
4. **AI 角色路由**：按分型自动选择 AI 角色（替记替查 / 出料出题 / 陪练镜子），并守住"不替做"红线。
5. **验收器**：三档验收题生成 + 未见情况随机抽题 + 撤 AI 终验。
6. **反馈回写**：验收失败自动回写归因，进入下一轮转化循环（五步 SOP 闭环）。

# 五、AnyJev 决策层设计（v2 新增）

> 本章节将 AnyJev（诺基亚应用研究 × 腾讯混元研究者开源，Apache 2.0）引入学习中间模块：把"判断"从"生成"中剥离，用校准过的概率驱动学习组件的自动决策（分型、验收、难度、误解检测），并保留人工介入的审计通道。

## 5.1 AnyJev 是什么

- **出身**：诺基亚应用研究（Nokia Applied Research）× 腾讯混元研究者联合开源，Apache 2.0；灵感来自 TypeSafe AI 的 Jev 接口，但**不绑定任务、不微调模型**——把任意现成 LLM 变成 Jev 式决策模型，**模型权重一个字节都不改**。
- **做法**：把判断写成类型化 Question（choice 选择题 / noul 是非题 / score 打分题），选项映射成 tokenizer 里的单 Token，一次前向后直接读这些 Token 的 logits；不生成文本、无需解析。一次前向可并行回答多个独立问题。
- **四级决策档位**：
  - **L0 零标签修顺序偏置**：K 个选项做 K 种循环移位、对数空间平均，再除掉无需标签估出的标签先验。实测 Qwen3-8B BANKING77 20 分类：选项翻转率 **0.230 → 0.073**（一条标签都没用）。
  - **L1 温度校准**：在 L0 之上做温度缩放，每题约 100–500 条标签。校准误差 ECE **0.240 → 0.095**；在"错误率≤5%"红线内可自动决策的流量 **7.7% → 52%**（准确率 0.747→0.807）。
  - **L2 闭式 head + 深度截断**：保留原模型，前向停在约 **2/3 深度**（如 Qwen2.5-7B 保留 28 块中的 18 块），用闭式求解的线性 head 从中间层隐状态直接读决策；没有梯度、没有新权重、无需第二个模型。反直觉结果：**模型更小、更快反而更准**（Qwen3-4B 追平微调过的专用模型 Laya）。每题 100–300 条标签，几秒解出；head 只有几 KB，23 个 head 共 1.8–4.4 MB。
  - **head 随系统自生长**：第 0 天零标签直接跑 L0；`observe()` 把业务回路里的标签（人工复核改动、真实结果）记下来，**约 30 / 60 / 120 条自动重解 head**；`level="auto"` 有 head 走 L2、没有走 L0；换问法/选项换序会被路由到同一 head，30 条无标签请求即可重新对齐（0.77→0.65–0.70→0.74–0.75）。"head 是系统反复回答同一问题时自己长出来的记忆"。
  - **部署**：支持 Qwen 等开源模型本地部署（vLLM `--task embed` 或 transformers），**数据不出本地**；每个 Decision 自带档位字段，下游可写 `require("L1")` 拒绝弱档位执行。

## 5.2 Choice / Score / Noul 三原语映射学习判断表

| 原语 | 在 Jev 中的含义 | 映射到学习中间模块的判断 |
|---|---|---|
| **Choice**（K 选 1） | 从固定候选集中选一个 | **学习对象分型**（判别/思考/运动/语言/决策/信息…）、**错误归类**（定义不清/边界不清/特征抓错/过度概括）、**策略路由**（补料/重练/撤辅助/换档） |
| **Score**（有序分档） | 在有序档位上打分 | **掌握度**（未掌握/部分/熟练…）、**卡点严重度**（轻微/中等/致命）、**练习质量**（正确性/推理链完整度/流畅度） |
| **Noul**（是/否） | 二值判断 | **是否真掌握**（能独立做出 vs 只是看过）、**是否误解**（把 A 当 B）、**是否需人工介入**（置信度过低转人工复核） |

> 设计要点：一次前向并行问多个问题——同一份作答材料同时得到 Choice（分型/归类）、Score（掌握度/质量）、Noul（是否掌握/是否误解），构成"卡点诊断包"。

## 5.4 Code + AnyJev + LLM 三层分工表

| 层 | 负责什么 | 典型动作（学习组件内） | 为何这样分 |
|---|---|---|---|
| **Code（确定性规则）** | 可硬编码的规则逻辑 | 打卡/全勤判定、客观题对错判定、复习间隔（艾宾浩斯曲线）、题包轮换、日志写入 | 规则明确、可测试、零成本 |
| **AnyJev（窄语义判断）** | 需要语义但结论可枚举的判断 | 分型（Choice）、验收通过与否（Noul + Score 门控）、难度档位（Score）、误解检测（Noul）、错误归类（Choice） | 固定候选集 + 校准概率可设阈值 → 自动化可审计；深度截断 + 开源模型 → 本地快而省 |
| **LLM（生成与推理）** | 需要生成文本/长推理的任务 | 讲解概念、生成变式题与正反例、复盘总结、陪练话术、材料配方生成 | 开放式输出是 LLM 强项，不参与高频窄判断 |

> 分工原则：**确定性留 Code，窄判断给 AnyJev，生成与推理归 LLM**。AnyJev 不抢 LLM 的"讲"，LLM 不抢 AnyJev 的"判"。

## 5.5 AnyJev 独有优势小结

| 优势 | 对学习组件意味着什么 |
|---|---|
| **顺序偏置修复** | 选项顺序不再影响掌握度/分型判断（翻转率 0.230→0.073）；同一份作答换个选项顺序，结论稳定 |
| **校准概率可设阈值** | 置信度是"真概率"而非语气词：>0.9 闭卷、0.7–0.9 加验、<0.7 回炉；自动化可审计，5% 错误率红线下 52% 流量免人工 |
| **head 自生长** | 机器版"渐构可泛化模型"：0 标签启动 → observe 收集标签 → 30/60/120 条自动长出 head；与《学习观》"例子→规律→未见情况验证"同构 |
| **深度截断 + 开源模型** | 前向停在 2/3 深度、模型更小更快反而更准（Qwen3-4B 追平专用微调模型）；Qwen 本地部署（vLLM/transformers）数据不出本地，适合投资、隐私等敏感学习场景 |
| **每决策自带档位** | 组件可写 `require("L1")` 式护栏：验收、自动放行等动作只允许在足够强的档位上执行，弱档位一律转人工 |
